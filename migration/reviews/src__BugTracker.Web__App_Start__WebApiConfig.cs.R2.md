## Rulebook gaps

- **G1. §3 runtime table omits `HttpConfiguration`, `GlobalConfiguration`, `RouteParameter`.** §3 says its table is "Contents (exhaustive)", but the `btnet.runtime.web` row does not list these three classes. They exist in `port/runtime/src/main/java/btnet/runtime/web/` and in `runtime-notes.md:35` ("HttpConfiguration/GlobalConfiguration/RouteParameter (WebApiConfig)"). This omission is what led the implementer to write F1, F2 and F4. Proposed rule: add `HttpConfiguration` (`MapHttpAttributeRoutes()`, `Routes()` → `HttpRouteCollection.MapHttpRoute(String, String[, Object])`), `GlobalConfiguration` (`Configure(Consumer<HttpConfiguration>)`, `Configuration`) and `RouteParameter` (`Optional`) to the §3 `btnet.runtime.web` row. Add a §2A row: `WebApiConfig.Register` is translated statement-by-statement over these types, `config.Routes` → `config.Routes()`, defaults anonymous object → `LinkedHashMap`, and `Global.asax.cs:28` → `GlobalConfiguration.Configure(WebApiConfig::Register)`.
- **G2. Path-segment `{id}` on `/api/*` is undecided.** The source route `api/{controller}/{id}` (`WebApiConfig.cs:16`, `id` optional) also accepts `/api/<controller>/<anything>`. §2A maps each controller to `@RequestMapping("/api/<Name minus Controller>")` only, so in the port `/api/BugQuery/5` is a 404 at routing. Under Web API 5.2.3 the route matches, and action selection then decides: none of `BugQueryController.Get`, `LoginController.Post` or `BugFromEmailController.Post` declares an `id` parameter (Controllers/*.cs). Proposed rule: state the expected status for `/api/<controller>/<segment>`. Either it is 404 as in the port, with `TODO(port): verify Web API 5.2.3 action selection with an unmatched {id} route value` (verification deferred under D-001), or the runtime/controller mapping also matches `/api/<Name>/{id}` and lets the action ignore it. Evidence: WebApiConfig.cs:16-17; RULEBOOK.md:670-673; Controllers/*.cs signatures.
- **G3. No inventory rows for `App_Start/WebApiConfig.cs`.** Per §5 this is an inventory bug. Proposed: add a row for `L12`/`L14` pointing at the G1 rule, so the next implementer does not have to decide it.
