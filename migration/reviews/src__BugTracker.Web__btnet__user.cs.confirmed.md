## Rulebook gaps

- **G1. Declared type of a concrete `Dictionary<K,V>` / `List<T>` / `HashSet<T>` field or local** (R1.G1, R2 gap 1). §2A gives the instance mapping (:164) and the declared types for interfaces (:148, :168), but not the declared type for a concrete collection. Here the implementer chose `Map`; WebApiConfig chose `LinkedHashMap`. The human picks one: (a) keep the concrete type (`LinkedHashMap`/`ArrayList`/`LinkedHashSet`) and use the interface only for interface-typed C# declarations (R1's proposal), or (b) always declare the interface (`Map`/`List`/`Set`) with a concrete instance (R2's proposal). Evidence: user.cs:60, search.aspx.cs:31,34,636,655-656, Mail/email.cs:312, ExtendedWebClient.cs:300-301.
- **G2. SQL parameters used as text macros** (R1.G2, R2 gap 2). The SQLString refactor left sites where a `@name` parameter was meant as text substitution: an identifier inside `[...]` (user.cs:142-143), and a column-list fragment `@ORG_COLUMNS` (user.cs:252,257,340). Neither the rulebook, §0.1, nor the inventory tags them. Proposed: an inventory tag `SQL_PARAM_AS_TEXT` with mandated `BUG(port)` text, and rows `src/BugTracker.Web/btnet/user.cs L340` (BUG(port), reproduce) and `L142` (BUG(port) latent, reproduce). Also do a one-time grep of `src/` for `\[@\w+\]` and for parameters bound to SQL fragments. Decision for the human at the next gate: should `copy_user` join §0.1 as a sanctioned fix? As written, self-registration, LDAP auto-create, and email auto-register fail in both the original and the port.
- **G3. Inventory row `src/BugTracker.Web/btnet/user.cs L137` misdescribes the ALTER** (R1.G3). The row treats `alter table orgs add [@name] int null` as working control flow and does not record that it adds the wrong column. It needs an inventory-side correction by the human.
