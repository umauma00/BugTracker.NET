## Not confirmed

- R1.F2 (DbUtil.java:222, J-C18 cast form for `foreach (SqlParameter param in cmd.Parameters)`): only R1 reports it, and the evidence does not show a defect. J-C18 (RULEBOOK.md:171) names the JDK-mapped `ArrayList` and `Hashtable.Keys`. For runtime facade collections whose .NET originals are also non-generic, the rulebook prescribes the typed enhanced-for: `foreach (DataRow dr in t.Rows)` → `for (DataRow dr : t.Rows())` (RULEBOOK.md:161), and S1-19 `for (DataColumn c : dt.Columns())`, justified by `implements Iterable<DataColumn>` (RULEBOOK.md:481). `SqlParameterCollection` is `Iterable<SqlParameter>`, and `Add` accepts only `SqlParameter`, so the typed form behaves identically. The rulebook is ambiguous here (gap G1), so the default applies: not confirmed. R1's own fix also says to keep the current line if G1 is adopted.

## Rulebook gaps

- **G1: J-C18 and runtime facade collections that implement `Iterable<T>`.** (R1.G1 = R2.G1.) Proposed rule: J-C18 applies only to the JDK-mapped non-generic collections (`ArrayList`, `Hashtable` keys/values). A runtime facade collection that implements `Iterable<T>` (`SqlParameterCollection`, `DataRowCollection`, `DataColumnCollection`, `DataView`) is iterated with the typed enhanced-for `for (T x : c)`. Evidence: `dbutil.cs:209`, `SqlParameterCollection.java:19`, RULEBOOK §2A `foreach (DataRow …)` row and S1-19.
- **G2: §6.5 citation form.** (R1.G2 + R2.G3, merged.) The rulebook does not say how to cite a decision that came from a rule, or a run of consecutive rows. Proposed rule: `// inventory:` names exactly one existing row key. A decision taken from the rulebook is cited as `// RULEBOOK §<sec> [<id>]`. A run of N rows with the same decision gets one citation per row, with no ranges. Rule-decided sites that have no inventory row (util.cs L327, L377) are reported in the batch report as missing rows (§5). Evidence: Util.java:262, :364, :414.
- **G3: the body of `Util.get_culture_info()`.** (R1.G3.) The rulebook does not cover `util.cs:266-270`. §2A maps calls to `CultureInfo.EN_US`, but .NET returns a fresh, mutable instance on each call. Proposed rule: the body becomes `return CultureInfo.EN_US;`, with the runtime instance treated as read-only. No source site in util.cs mutates it; a survey of other units is still needed.
- **G4: `final` on a mutable static field that is never reassigned.** (R2.G2.) Proposed rule: a static field that is initialized at its declaration and never assigned anywhere in `src/` may be `final`. A field assigned anywhere (for example `Util.context`, `util.cs:52`) must not be. Separately, the human resolves the conflicting duplicate inventory rows for util.cs L39 and L40 (REGEX_SAME, which has no `final`, and STATIC_CONST_LIKE, which has `final`).
