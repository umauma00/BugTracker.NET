## Rulebook gaps

G1 (R1.G1, R2.G1) **Which logger receives the file appender.** RULEBOOK.md:644 does not name it. Proposed: "`LoggingConfig.Configure()` never calls `LoggerContext.reset()` and never touches root. It configures logger `btnet` (`detachAndStopAllAppenders`, `addAppender(file)`, `setLevel(TRACE|OFF)`, `setAdditive(false)`), which covers application code and `btnet.runtime.*` (including the §3 `btnet.runtime.Threads` FATAL handler). Framework logging stays on Boot's defaults." Evidence: `LoggingConfig.cs:32`, `Global.asax.cs:22`, `util.cs:74`, `manage_logs.aspx.cs:35`. C1 depends on this.

G2 (R1.G2, R2.G3) **Atomic swap versus reset-first.** Proposed: "read every setting and build/start every appender first; attach to the logger as the final statements, at the `LogManager.Configuration = config` position." Evidence: `LoggingConfig.cs:12,37`, `util.cs:620-626`.

G3 (R1.G3) **Eager file creation.** State whether an empty `btnet_log.txt` created with `LogEnabled=0` is an accepted divergence (D-006 style) or must be avoided (lazy appender, if the Boot-managed Logback offers it).

G4 (R1.G4, R2.G2) **Archive file name.** Pin `<log folder>/btnet_log.%d{yyyyMMdd}.txt` (NLog 3.x default `ChangeExtension(FileName, ".{#}"+ext)`), keeping the `TODO(port)` until it is verified against NLog 3.1.0 (`packages.config:27`). Evidence: `manage_logs.aspx.cs:35` filters on `*.txt`.

G5 (R1.G5, R2.G5) **Line ending, encoding and exception text of the file layout.** NLog 3.1 FileTarget defaults are `\r\n` (Windows `Environment.NewLine`) and `Encoding.Default` (windows-1252), and the default layout has no `${exception}`. The pinned pattern uses `%n` (`\n` on Linux), the encoder is UTF-8, and Logback PatternLayout appends `%ex` on its own when the pattern has no throwable converter. §1 String policy pulls in both directions. Pin `%nopex`, the line ending and the charset, or record the differences as accepted.

G6 (R1.G6) **Mail rule level mapping.** When the FATAL mail appender TODO is resolved, the rule should say "threshold ERROR + `FATAL` marker filter (e.g. `EvaluatorFilter` with `OnMarkerEvaluator`)", consistent with RULEBOOK.md:643. C4 records this in a comment in the meantime.

G7 (R2.G4) **FATAL level name in the file.** `%level` prints `ERROR` for a `Fatal` call mapped to `error(FATAL marker)` (`Global.asax.cs:23`), while NLog prints `FATAL`. Either add a runtime converter that prints `FATAL` for marker-carrying events, or accept the difference explicitly.

G8 (R2.G6) **Inventory coverage.** `inventory.tsv` has no rows for this unit. §5 should say that a unit covered by a dedicated §2A row needs none, or rows should be added for `LoggingConfig.cs` L15-17, L20-28 and L31-35.
