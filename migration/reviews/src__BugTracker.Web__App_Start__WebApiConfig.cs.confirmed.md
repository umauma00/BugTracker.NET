## Rulebook gaps

- **G1 (R1.G1, R2.G1). The §3 `btnet.runtime.web` "Contents (exhaustive)" row omits `HttpConfiguration` (+`HttpRouteCollection`), `GlobalConfiguration` and `RouteParameter`.** These classes exist (§3.1 [D-009] index; `runtime-notes.md:35` "HttpConfiguration/GlobalConfiguration/RouteParameter (WebApiConfig)"). This omission caused C1-C3. Proposal:
  - Add the three classes to the §3 row with their members: `MapHttpAttributeRoutes()`, `Routes()` → `HttpRouteCollection.MapHttpRoute(String, String[, Object])`, `Configure(Consumer<HttpConfiguration>)`, `Configuration`, `Optional`.
  - Add a §2A row in the style of `Startup` J-C14: `WebApiConfig.Register(HttpConfiguration config)` is translated statement by statement, `config.Routes` → `config.Routes()`, and the defaults anonymous object → `LinkedHashMap` with `RouteParameter.Optional`.
  - Map `Global.asax.cs:28` → `GlobalConfiguration.Configure(WebApiConfig::Register)`.
  - State that the recorded routes are metadata only and that Spring routing follows §2A Web API.
  - Note: §3.1 already settles existence, but §3's "exhaustive" wording still contradicts it. Either update §3 or drop "exhaustive".
- **G2 (R1.G2, R2.G2). The optional path-segment `{id}` and the trailing slash on `/api/*` are undecided.** §2A (RULEBOOK.md:670-673) maps each controller only to `@RequestMapping("/api/<Name minus Controller>")`. In the source, `DefaultApi` also matches `/api/<controller>/<segment>` and `/api/<controller>/`. No action declares `id` (`BugQueryController.cs:9`, `BugFromEmailController.cs:16`, `LoginController.cs:12`), so Web API most likely still selects the action. With trailing-slash matching off by default, Spring Boot 4 returns 404 for both URLs. Proposal: either map `{"/api/<Name>", "/api/<Name>/", "/api/<Name>/{id}"}` and ignore `{id}`, or accept the 404 as a logged latent divergence. In both cases add `TODO(port): verify Web API 5.2.3 action selection with an unmatched {id} route value` until the original can run (D-001).
- **G3 (R1.G3). The anonymous-object → `LinkedHashMap` rule is scoped to the Web API JSON section** (RULEBOOK.md:686), but `WebApiConfig.cs:17` is an anonymous object outside a JSON response. Proposal: move the rule to §2A General conventions so it applies in every context.
- **G4 (R2.G3). There are no inventory rows for `App_Start/WebApiConfig.cs`.** §5 treats this as an inventory bug, which the implementer must flag in its batch report (check whether it was flagged). Proposal: add rows for `L12`/`L14` that point at the G1 rule.
