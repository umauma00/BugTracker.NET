## Rulebook gaps

1. **Citation granularity for §6 item 5.** (R1 obedience note on L81/L83; R2.G3.) The rulebook does not say whether one `// inventory:` comment covers several rows implemented by the same block or statement (L55 covering L56/L58/L60; L79 covering L81/L83). Proposed rule: "One citation per translated statement whose decision came from a row; a compound statement may cite only its first row when every other row it implements is a sub-expression or nested statement of it." Evidence: inventory rows 414-423; target :64, :100.
2. **Index argument to `ElasticClient.Search`.** (R1 gap 4; R2.G2.) C29 and §3 :1176 give `Search(String index, String jsonBody)` but do not say what to pass for NEST's implicit default index. Inventory L55 uses the literal `"btnet"`; `_client.DefaultIndex()` or `null` (runtime fallback, `ElasticClient.java:88`) are equally plausible. Proposed rule: pin one form in the NEST row (for example `_client.Search(_client.DefaultIndex(), body)`, or ratify `"btnet"`). Evidence: `BugSearch.cs:55`, `BugSearchFactory.cs:19-22`.
3. **Marker cardinality and placement for rulebook-level TODOs.** (R1 gap 3; R2.G1.) (a) Rows L55 and L79 both mention `TODO(port): verify NEST 1.0.2 wire format`, and the rulebook does not say whether that means one marker per unit or one per site. (b) The J-C17 "JSON null" `TODO(port)` at §2A :184 does not say whether sites carry a marker. The parallel date note at :505-510 says explicitly that they carry none (S1-43). As a result, `todos=` counts can differ between implementers (1, 2 or 4). Proposed rule: "A TODO the rulebook states once for a construct family is placed once per unit, at its first site", and append to :184: "This TODO is rulebook-level; translated units carry no site marker for it (as S1-43)."
4. **Json.NET date parsing of `_source` string fields.** (R1 gap 1.) NEST 1.0.2 / Json.NET's default `DateParseHandling.DateTime` turns ISO-looking strings in `desc`/`status` into `DateTime` values. `ToString()` then renders those in en-US `G` format, while Java keeps the raw string. Proposed rule: extend the J-C17 TODO (§2A :184, runtime-owned) so the runtime author confirms NEST's serializer settings. The author then either emulates this in `ElasticClient.Search` when building `Hit.Source`, or records it as an accepted divergence in D-006. Evidence: `BugSearch.cs:72,78,87`.
5. **General LINQ `FirstOrDefault()` row is null-unsafe.** (R1 gap 2.) §2A :175 maps it to `findFirst().orElse(null)`, which throws an NPE on a null first element, where .NET returns null. Proposed rule: for a `List` source use `xs.isEmpty() ? null : xs.get(0)`, and use `findFirst()` on a stream only when the elements are known to be non-null.
6. **Names for locals introduced by sanctioned rewrites.** (R2.G4.) The NEST lambda-to-JSON rewrite introduces locals (`highlight_` was renamed to avoid clashing with the source's `var highlight`). The rulebook sanctions a trailing `_` only for Java keywords (§2A :130, §4 :1789). Proposed rule (§2A General): "Locals introduced by a sanctioned rewrite take a name not used elsewhere in the method; on a clash with a source name, append `_`." Evidence: target :70-79 vs :102; src :58, :81.
