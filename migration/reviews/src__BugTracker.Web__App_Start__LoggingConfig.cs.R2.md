## Rulebook gaps

G1. **Which logger receives the file appender.** RULEBOOK.md:644 says "level TRACE if `LogEnabled=1` else OFF" but does not name the logger. NLog `"*"` covers only NLog loggers, which in practice means application code only. In Logback, root also covers every framework library. Proposed rule: "attach the file appender to logger `btnet` (application + `btnet.runtime.*`), level TRACE/OFF from `LogEnabled`; root keeps no btnet appender". Evidence: `LoggingConfig.cs:32`, `util.cs:74`, `Global.asax.cs:22`, `manage_logs.aspx.cs:35` (the file is a user-visible artifact).

G2. **Archive file name.** The rule leaves "archive naming per NLog `ArchiveNumbering=Date`" as an open TODO, and two implementers could pick different suffixes. Proposed rule: `fileNamePattern = <log folder>/btnet_log.%d{yyyyMMdd}.txt` (NLog 3.x default `ChangeExtension(FileName, ".{#}"+ext)`, Day ⇒ `yyyyMMdd`; verify against NLog 3.1.0 `FileTarget`). Evidence: `manage_logs.aspx.cs:35` filters on `*.txt`.

G3. **Order of configuration vs `reset()`.** Proposed rule: build and start every appender, and read all settings, before `LoggerContext.reset()`; reset and attach at the `LogManager.Configuration = config` statement. Evidence: `LoggingConfig.cs:37`, `util.cs:621-626` (`get_log_folder` can throw).

G4. **FATAL level name in the file.** The pinned pattern uses `%level`, so a `Fatal` call (`Global.asax.cs:23`) mapped to `error(FATAL marker)` prints `ERROR` where NLog's `${level:uppercase=true}` prints `FATAL`. Proposed: a runtime converter (for example `%btlevel`) that prints `FATAL` when the event carries the `FATAL` marker, or an explicit rule that this difference is accepted ("Not judged").

G5. **Line ending, encoding and exception text of the file layout.** For a FileTarget, NLog 3.1 defaults to `LineEnding=Default` (Environment.NewLine = `\r\n` on Windows) and `Encoding=Encoding.Default` (windows-1252). Its default layout has no `${exception}`. The pinned pattern uses `%n` (`\n` on Linux), the encoder charset is unset (JVM default UTF-8), and Logback's PatternLayout appends `%ex` on its own when the pattern has no throwable converter. §1 String policy (`Environment.NewLine = "\r\n"`, "text I/O UTF-8") pulls in two directions here. Proposed: either pin `…|%msg%nopex\r\n` (literal CRLF) and a charset, or record the differences as accepted, since the file is "Not judged" but is downloadable by admins.

G6. **Inventory coverage.** There are no inventory rows for this unit. If the rule row is meant to stand in for rows, §5 should say that a unit covered by a dedicated §2A row needs none; otherwise add rows for `LoggingConfig.cs` L15-L17, L20-L28 and L31-L35.
