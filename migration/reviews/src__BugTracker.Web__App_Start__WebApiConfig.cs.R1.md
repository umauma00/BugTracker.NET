## Rulebook gaps

G1. **§3 is silent on the Web API configuration types that the runtime ships.** `btnet.runtime.web.HttpConfiguration` (+ nested `HttpRouteCollection`), `GlobalConfiguration` and `RouteParameter` exist in `port/runtime`, but the §3 `btnet.runtime.web` row ("Contents (exhaustive)") does not list them, and §2A has no row for `WebApiConfig`/`GlobalConfiguration.Configure`. That gap is what led the implementer to believe the type did not exist. Proposed rule (in the style of the `Startup` J-C14 row at §2A:133): "`App_Start/WebApiConfig.cs` → `public static void Register(HttpConfiguration config)` with both calls kept over runtime `HttpConfiguration` (`MapHttpAttributeRoutes()`, `Routes().MapHttpRoute(name, routeTemplate, defaults)`, `defaults` a `LinkedHashMap` with `RouteParameter.Optional`). `Global.asax.cs:28` → `GlobalConfiguration.Configure(WebApiConfig::Register)`. The recorded routes are metadata only; Spring routing is per §2A Web API." Also add `HttpConfiguration`, `GlobalConfiguration`, `RouteParameter` to the §3 `btnet.runtime.web` row.

G2. **The optional `{id}` segment and trailing slash of `api/{controller}/{id}` are not decided.** §2A:671-673 maps the route to `@RequestMapping("/api/<Name minus Controller>")` only. In .NET, `DefaultApi` also matches `/api/BugQuery/5` (id is an optional path segment, `WebApiConfig.cs:16-17`) and `/api/BugQuery/`. None of the three actions has an `id` parameter (`BugQueryController.cs:9`, `BugFromEmailController.cs:16`, `LoginController.cs:12`), so Web API would most likely still select the action and ignore the extra route value. Spring Boot 4 (trailing-slash matching off by default) returns 404 for both URLs. The translation's comment at `:12` ("{id} is bound by name from the query string") misdescribes the source route. Proposed rule: controllers map `{"/api/<Name>", "/api/<Name>/", "/api/<Name>/{id}"}` with `{id}` ignored, or the rulebook explicitly accepts the 404 as a latent divergence in the deviation log. Either way add `TODO(port): verify Web API 5.2.3 action selection with an unmatched {id} route value` until the original can run (D-001).

G3. **The anonymous-object rule is scoped to the Web API JSON section** (§2A:686, "Anonymous objects → `LinkedHashMap` built in declared order"). `WebApiConfig.cs:17` is an anonymous object outside a JSON response. Proposed: move the rule to §2A General conventions so it applies in every context.
