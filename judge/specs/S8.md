# S8 — Notification queue

Test class: `judge/src/test/java/judge/scenarios/S8_NotificationQueueTest.java`.

## Headline: the original never writes a `queued_notifications` row

`Bug.send_notifications` queues each mail with one batch (btnet/bug.cs:1178-1183):

```sql
delete from queued_notifications where qn_bug = @bug and qn_to = @to
insert into queued_notifications (...) values (getdate(), @bug, @user, N''not sent', 0, ...)
```

`N''not sent'` (a C# verbatim string, so `''` stays two quotes) is a T-SQL syntax error,
so the whole batch fails to compile: nothing is deleted, nothing inserted, and the
SqlException propagates out of `edit_bug.aspx` (no try/catch, edit_bug.aspx.cs:823-829)
as an unhandled 500 — **after** the bug UPDATE has committed (edit_bug.aspx.cs:761-786).
For a non-admin subscriber the loop fails even earlier: `Security.GetIdentity` reads
`dr["project_admin"]`, which its SQL never selects (Security.cs:21-35,117). Either way:
a qualifying subscriber ⇒ HTTP 500, bug saved, queue untouched. No qualifying
subscriber ⇒ normal page, `msg` = `Bug was updated.`, queue untouched.

All of this is pinned with `@Inherited`. The judge can therefore not observe the
"which rows with which subject/body" contract the task asked for; the subject format
(`$THING$:$BUGID$ was $ACTION$ - $SHORTDESC$ $TRACKINGID$`, Web.config:180, bug.cs:1116-1148),
`qn_from` (`NotificationEmailFrom`, Web.config:164) and body (print_bug HTML with
`<base href=AbsoluteUrlPrefix>`, bug.cs:1158-1174) are documented here for the port but
**not judged**, because the original can never produce them. If the defect is fixed later
(prompt 06), these become the expected values.

## How the edit is driven

1. `GET edit_bug.aspx?id=1&user_hit_submit=1`, then submit that page's form (`Form`,
   field `short_desc` changed, no button) to the form's action.
2. Why the query parameter: edit_bug saves only if `Request["user_hit_submit"] == "1"`
   (edit_bug.aspx.cs:100,142-146). No element of that name is rendered (edit_bug.aspx;
   EditBug.ts:202-204 sets a nonexistent `#user_hit_submit`), so a plain browser post
   never saves (pinned as `plainFormPostNeitherSavesNorNotifies`). `Request[]` also reads
   the query string, and a WebForms form posts back to its own URL including the query
   string, so this is the only public way to reach the save path.
   **Binding on the port:** `edit_bug.aspx` must honour `user_hit_submit=1` in the query
   string of the POST, and its form must post back to the URL it was loaded from
   (query string included).

## notifications.aspx / edit_queued_notifications.aspx (admin)

- `table#notifications-table` (binding): header `id, data created, to, bug, status, retries, last error`
  (sic), rows ordered by `qn_id`, cell = raw value (notifications.aspx:97-124, .cs:163-166).
- `edit_queued_notifications.aspx?actn=delete` deletes rows with `qn_status = N'not sent'`;
  `actn=reset` sets `qn_retries = 0` on those rows; both then 302 → `notifications.aspx`
  (edit_queued_notifications.aspx:24-42).
- **@Inherited**: the rendered "Delete unsent notifications" link is
  `edit_queued_notifications.aspx?actn=delete %>` (notifications.aspx:82), so following it
  deletes nothing. The test locates the link by its exact text and percent-encodes the
  href as a browser does.
- **@Inherited**: any `ses` query parameter → body exactly
  `session in URL doesn't match session cookie`, nothing done (Session["session_cookie"] is
  never assigned anywhere; :18-22).

- `notifications.aspx` column `data created` is not judged: `DateTime.ToString()` in server culture.

## Not judged, and why

- Subject, from, body, qn_user of a queued row — the original cannot write one (above).
- `NotificationEmailEnabled=0` (global switch, bug.cs:1006-1011) — runtime config the judge cannot change.
- `actn=resend` / the mail-sending thread (sleeps 60 s, needs SMTP; bug.cs:1212-1292).
- The 500 page body (YSOD) and anything after the exception.
- Notifications from other actions (edit_comment, edit_attachment, edit_task, merge_bug,
  send_email, new bug insert) — same broken code path; covered here once via edit_bug.
- Search indexing called at the top of send_notifications (EnableSearch=1, exceptions swallowed, Search/BugSearch.cs:118-160).
