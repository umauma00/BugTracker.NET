## Which search paths exist

| Path | Backend | Judged? |
|---|---|---|
| `search.aspx` — form-based query builder | SQL Server (`do_query`, search.aspx.cs:277-622) | **Yes** |
| `search_text.aspx?query=…` — navbar text search | Elasticsearch via NEST (Search/BugSearchFactory.cs, Search/BugSearch.cs), `SearchServerURI=http://localhost:9200`, `EnableSearch=1` (Web.config:798-799) | Only the empty-query message, which ends the response before Elasticsearch is called (search_text.aspx.cs:17-27,35-60) |

**Why the Elasticsearch path is not judged:** with a query, `search_text.aspx`
calls `ElasticClient.Search` unconditionally (search_text.aspx.cs:29-30). There is
no SQL fallback and no disabled branch (`EnableSearch` only hides the navbar
form, Controls/MainMenu.ascx:71). What happens when the server is unreachable
depends on the NEST version's error behaviour (throw vs. empty invalid response)
and on whether something listens on localhost:9200 on the host — neither is
determinable from source. The index contents also depend on prior indexing.
`SearchSQL` (custom SQL for search.aspx) is commented out (Web.config:540-555),
so the built-in SELECT applies.

## How a search is submitted

`GET search.aspx`, then post the form containing `like`, with
`hit_submit_button=1` — what the Search button's onclick does
(search.aspx:140-141,342-344; search.aspx.cs:148-152). The field is set only if
the form has it (it is browser-side plumbing; a port may run the search on any
submit). List boxes are set with all selected values.

## Result reading

- Result ids = ids of links to `edit_bug.aspx?id=N`, in document order (the
  description cell is such a link, bug_list.cs:808-813). Order is `bg_id desc`
  (search.aspx.cs:607).
- Full row = normalized cell texts of the `tr` holding that link. For an admin the
  list is rendered inside the mass-edit form with a leading checkbox cell
  (search.aspx:400-403, bug_list.cs:671), the color column produces no cell, and
  columns are: sel, id, desc, reported by, reported on, last updated by, last
  updated on, project, organization, category, priority, assigned to, status
  (search.aspx.cs:452-560; no tags column — EnableTags 0; no UDF — ShowUserDefinedBugAttribute 0).
- Count line `N bugs returned by query` (bug_list.cs:42-51) and empty result
  `No bugs` (search.aspx:426-433) are matched as text contained in the page
  (they have no element id).

## Steps and expectations

1. `anonymousSearchRedirectsToLogin` — 302 → `default.aspx`, `returnUrl=<base>search.aspx`.
2. `getShowsFormWithoutResults` — fields `reported_by category priority assigned_to
   status org project like like2 and_or` exist; `and_or` defaults to `and`; no result
   links, no count line.
3. `descriptionSearchIsCaseInsensitiveNewestFirst` — like `alpha` → [4, 1]; row 1 =
   `| 1 | alpha login fails | admin | 2020-01-15 | admin | 2020-01-15 | project 1 | org1 | bug | high | developer | new`
   (leading empty sel cell); page contains `2 bugs returned by query`.
   Case-insensitivity comes from the shared database's collation, so it is
   identical for both implementations as long as the port uses SQL `LIKE`.
4. `likeEscapesSqlWildcards` — `50%` → [2] (`%` literal); `discount_50` → [] (`_`
   literal); `o'brien` → 200 and [] (search.aspx.cs:312-315).
5. `noonTimestampIsShownAsDateOnly` **@Inherited** — bug 2 row
   `| 2 | beta discount 50% off | tester | 2020-02-01 | admin | 2020-02-02 | project 2 | developers | enhancement | med | | in progress`
   — 12:00:00 is shown without time (btnet/util.cs:302-305).
6. `orLogicUnionsCriteria` — status `new` OR like `gamma` → [4, 3, 1]; with `and` → [].
7. `listboxCriteriaWithAndLogic` — category bug AND priority med → [4];
   assigned_to `[not assigned]` (value 0) → [4, 2]; project 1 AND priority in (high, low) → [3, 1].
8. `noMatchSaysNoBugs` — like `zzz-nothing` → no results, page contains `No bugs`, no count line.
8a. `searchPageDependsOnOrgSearchPermissionForNonAdmins` **F4 (new)** — fixture non-admin in
    org1 (`og_can_search` 1): `search.aspx` 200 with the form (`and_or` = `and`); fixture non-admin in
    an org with `og_can_search = 0`: 200, text contains `You are not allowed to use this page.`,
    no `like` field (search.aspx.cs:40-49).
9. `textSearchWithoutQueryShowsMessage` — `search_text.aspx?query=` and
   `search_text.aspx` → 200, page contains `You forgot to enter something to search for...`.

## Not judged, and why

- Elasticsearch text search with a query (see above).
- Result lists seen by a non-admin: depend on per-user permission claims (including the
  duplicate `CanOnlySeeOwnReportedBugs` claim at Security.cs:73, shadowed by :49 because
  `FindFirst` returns the first claim — preserved; RULEBOOK [J-C3]) and are not judged; only the
  permission gate is (test 8a).
- Date-range criteria (`from_date` etc.): `format_local_date_into_db_format`
  depends on server culture.
- Sorting/filtering/paging of the result list via `actn`/`filter`/`new_page`
  (session-state UI plumbing), project custom dropdowns, "suggest", save-as-query.
- Comment search (`like2`): needs bug_posts fixtures with `bp_comment_search`; left to the bug-edit scenario.
