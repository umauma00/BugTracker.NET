## Fixtures

- **Priming.** Whether the very first `admin`/`admin` attempt on a fresh
  setup.sql works depends on the seeded hash (unverifiable without running the
  original). Tests that need a deterministic first success first submit one
  wrong `admin` password (`primeAdminPassword`): afterwards user 1's password is
  exactly `admin`.
- **Users that can log in.** `copyAdminCredentialsTo(name, us_admin)` inserts a
  user (org 1, default query 1) whose `us_salt`/`us_password` are copied from
  user 1 *after* priming, so its password is `admin`. The hash does not depend
  on the username. This is the only deterministic way to get a second loginable
  user without the admin UI (S6 covers UI-created users).
- Usernames for lockout tests carry a random suffix: the failure list lives in
  the application cache (not the DB) for 10 minutes, so a fixed name would
  carry state between runs against one app instance.
- "Logged in" probe: `GET bugs.aspx` without following redirects answers 200.

## Steps and expectations

1. `loginPageIsAnonymousAndHasLoginForm` — `GET default.aspx` → 200, form with
   `user`, `pw`; `msg` text empty.
2. `adminLoginLandsOnBugsAndStampsLoginTime` — prime; login admin/admin →
   exactly one redirect, to `bugs.aspx`; final 200; `users.us_most_recent_login_datetime`
   (id 1) no longer the seeded `2015-01-13 22:05:16.973`; logged in.
3. `wrongPasswordShowsMessageAndStaysOnLoginPage` — admin/wrong → 200 on
   `default.aspx`, no redirect, `msg` = `Invalid User or Password.`, not logged in.
4. `unknownUserGetsSameMessageAndDoesNotTouchAdmin` — same message; user 1's
   `us_salt`/`us_password` unchanged (still seeded salt `PmafvZSWFYML3`).
5. `inactiveUserGetsSameMessageAndDoesNotTouchAdmin` — `guest`/`guest`
   (us_active 0) → same message; user 1 unchanged.
6. `failedAdminAttemptRewritesAdminPassword` **@Inherited** — admin/wrong →
   user 1 `us_salt` ≠ seed, alphanumeric, length 10–99; `us_password` changed;
   a fresh session then logs in with admin/admin on the first try.
7. `seededNonAdminLoginFailsWithServerError` **@Inherited** — developer/admin →
   HTTP 500; user 1 salt rewritten; developer's login time still NULL; not logged in.
8. `nonAdminWithCorrectPasswordFailsWithServerError` **@Inherited** — fixture
   non-admin with password `admin` → form login 500, login time stamped, not
   logged in; `api/login` for the same user → 500, not logged in.
9. `anonymousProtectedPageRedirectsToLoginWithReturnUrl` — `GET bugs.aspx?queryId=1`
   → 302, Location path `default.aspx`, `returnUrl` (decoded) =
   `<base path>bugs.aspx?queryId=1`; `logoff.aspx` anonymous likewise.
10. `loginIgnoresReturnUrl` **@Inherited** — anonymous `admin.aspx` lands on
    `default.aspx?returnUrl=<base>admin.aspx`; logging in from that page lands on
    `bugs.aspx`, not `admin.aspx`. (The form must post back to its own URL with
    the query string, as WebForms does.)
11. `loginHonoursLocalUrlParameterOnly` — `default.aspx?url=<base>admin.aspx&qs=`
    → login lands on `admin.aspx`; `url=http://example.com/evil.aspx` → lands on
    `bugs.aspx` on the judged host.
12. `logoffSignsOutAndRedirectsWithMessageParameter` — `GET logoff.aspx` → 302
    to `default.aspx` with `msg=logged off`; that page's `msg` is empty;
    afterwards not logged in.
13. `adminSeesAdminMenu` — on the landing page, same-host links include
    `bugs.aspx search.aspx queries.aspx reports.aspx admin.aspx edit_self.aspx logoff.aspx`,
    exclude `users.aspx` and `view_whatsnew.aspx`; a form whose action is
    `search_text.aspx` contains a field named `query`.
14. `elevenFailuresLockTheAccount` — 11 wrong attempts, then the correct
    password → still `Invalid User or Password.`, no redirect, user 1
    credentials unchanged by that last attempt.
15. `tenFailuresDoNotLock` **@Inherited** (off-by-one, `>` not `>=`) — 10 wrong
    attempts, then the correct password → lands on `bugs.aspx`.
16. `apiLoginSuccessReturns200EmptyAndSignsIn` — a wrong API attempt (403)
    primes; `{"User":"admin","Password":"admin"}` → 200, empty body; cookie
    then works for `bugs.aspx`.
17. `apiLoginFailureReturns403Empty` — unknown user → 403, empty body, not
    logged in, user 1 untouched.

## Normalization beyond N1–N3

- **Logical element id.** `clientIDMode="AutoID"` (Web.config:38) renders a
  server control `id="msg"` inside a master page as `ctl00_body_msg`. The judge
  looks up `#msg` and falls back to `#ctl00_body_msg` (`logicalText`). This is the
  id counterpart of the logical *field* name rule; it should move into
  `Norm` (core change requested).

## Inherited quirks pinned

Admin password rewrite on every attempt (6, also 7); seeded non-admins crash
(7); every non-admin crashes on sign-in (8); `returnUrl` ignored (10);
lockout off-by-one (15).

## Not judged, and why

- **Admin-only menu items absent for a non-admin**: no non-admin can sign in
  (test 8), so there is no non-admin page to inspect. Pinned instead as the crash.
- First admin login on a pristine database (seeded hash unverifiable).
- Lockout window expiry (10 minutes — timing), LDAP / Windows auth (settings 0),
  `mobile` redirect to `mbugs.aspx`.
- Exact 500 error page body (framework yellow screen).
- The exact `us_most_recent_login_datetime` value (wall clock); only "changed /
  set" is asserted.
