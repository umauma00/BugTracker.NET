## Data-bearing handles (binding on the port)

- print_bugs: the page's (single) `table`, header row first.
- print_bug / print_bugs2: bug fields as **two-cell table rows `label | value`** in a table
  that contains the `Last changed by` row; links whose href ends in `edit_bug.aspx?id=N`
  (link text = id, then short description). Only the path suffix of those hrefs is
  judged: the prefix is the `AbsoluteUrlPrefix` setting (Web.config:128).
- `#posts_table` (print_bug.cs:310-314).
- CSV: bytes after the BOM, CRLF line structure, quoting.

## Normalization beyond N1–N3 (justified)

- **Row order of print_bugs / the CSV export is not judged** (rows sorted by id before
  comparing): BugQueryExecutor's outer SELECT has no ORDER BY (see S2.md). Row
  membership per page is judged. The tasks export *is* ordered (outer `order by`).
- **print_bugs date cells** (non-null `reported on`, `last updated on`) are not judged:
  they are `DateTime.ToString()` in the server's thread culture (print_bugs.aspx.cs:155),
  which no source file fixes (Web.config:47 leaves `<globalization>` commented out).
  Null date cells (empty) are judged.
- **Content-Type** compared lower-cased with spaces removed
  (`application/ms-excel;charset=utf-8`): ASP.NET appends `; charset=utf-8` itself; spacing/case is framework formatting.
- **Content-Disposition file name**: timestamp part (`DateTime.Now`, util.cs:1166) only
  checked against the pattern `btnet_\d{8}_\d{6}\.csv`.
- **posts_table**: the `how_long_ago` part (`N days ago`, relative to now) is matched as
  `\d+ days ago`; everything else exact.

## Not judged, and why

- Flag/seen state in print_bugs (only a CSS class on an empty span).
- `history_inline` / `images_inline` cookies (the harness has no cookie-setting API) —
  defaults (both off) are judged.
- Non-midnight times (DateTimeFormat `yyyy-MM-dd h:mm tt` uses culture AM/PM designators).
- Cache headers (`do_not_cache`) — HTTP plumbing.
- print pages for unauthorized users / bugs without permission (S1/S3 territory).
